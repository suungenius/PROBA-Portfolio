# Тестирование и приёмка

## Трассировка требований

| Тест | Требование | Условие | Что сверять после команды |
|---|---|---|---|
| TC-01 | FR-02, NFR-01 | Два одновременных запроса на одну версию с разными ключами | Один идентификатор прохождения, одно использование права |
| TC-02 | FR-02, NFR-01 | После расхода права вставка прохождения завершается ошибкой | Откат расхода. Нет нового прохождения |
| TC-03 | FR-03 | Две вкладки сохраняют одну исходную ревизию | Первая запись сохраняется. У второй HTTP 409. Повторное чтение возвращает новую ревизию |
| TC-04 | FR-04 | Повтор той же сдачи и повтор ключа с другой ревизией | Одна сдача для повтора. HTTP 409 для команды с изменённой ревизией |
| TC-05 | FR-05, NFR-02 | Прямое чтение будущего задания или чужой работы | Никаких данных закрытого задания. Чужая история недоступна |
| TC-06 | FR-06, NFR-03 | Нет оснований для уверенной оценки после разрешённых повторов | Сдача доступна для ручного разбора. Позиция сохраняется |
| TC-07 | FR-05, FR-07 | Доставка принятой оценки дважды, включая финальное задание | Один итог и не более одного перехода. Завершение только после последней позиции |
| TC-08 | NFR-02, FR-07 | Открытие завершённого прохождения и попытка сохранить черновик | Владелец видит историю. Запись отклоняется |
| TC-09 | FR-05, NFR-01 | Результат проверки приходит после отмены | Отмена остаётся конечным состоянием. Поздний результат не создаёт оценку или артефакт и не продвигает прохождение |

Идентификаторы требований приведены в [матрице требований](02-requirements-and-processes.md). Для TC-01 и TC-02 важно проверять состояние БД и расход права доступа. Успешный HTTP-ответ сам по себе не выявляет дубль.

## От дефекта до регрессии

В раннем сценарии повтор со свежим ключом мог создать ещё одно прохождение той же версии. Правило уточнили и добавили проверки двух одновременных активаций с разными ключами, повторного открытия паузы и возобновления при уже активном экземпляре этой версии. Контроль побочных эффектов включает проверку идентификатора, состояния и числа использований права доступа. [Последствия изменения](06-decisions-and-risks.md).

## Какие проверки подтверждены

| Свидетельство | Что проверено |
|---|---|
| Интеграционные тесты исходного проекта | В коде есть проверки конкурентной активации, отката расхода, ревизий черновика, повторной сдачи, поздней оценки и серверной авторизации. Сами тесты отдельно при подготовке портфолио не запускались |
| Исторический GitHub Actions от 8 ноября 2026 года | На ветке изменения перед слиянием все 6 задач завершились успешно, включая общую проверку, проверки отдельных кейсов, evaluator и подготовку benchmark. Это результат конкретной ревизии PR |
| Браузерная проверка от 20 ноября 2026 года | Без входа открылись главная, каталог с 13 профессиями и страница бизнес-аналитика. Статус покупок и скриншоты зафиксированы на открытом сайте |
| Проверка двух SQL-примеров | Оба запроса выполнены на изолированном PostgreSQL 18 после применения 33 миграций исходной схемы. Результаты совпали с ожидаемыми для синтетических активаций и сдач |

Критерии технической приёмки прежде всего защищают целостность данных и доступ. При решении о выпуске отдельно проверяются готовность среды, качество содержательной оценки, опыт участников пилота и применимые условия запуска. [Основания и границы выводов](07-contribution-and-evidence.md).
